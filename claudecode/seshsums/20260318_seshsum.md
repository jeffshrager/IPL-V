### 2. Per-proof graph generation for all theorems

**Key discovery:** `ipl-eval` is only called recursively for J1/J18/J100
subprocesses. M001 (the LT Executive) is entered via the interpreter's flat
DESCEND loop (H1 stack), so a CLOS `:around` method on `ipl-eval` cannot
intercept it.

**Confirmed empirically:** At `M001R000`, H0 and W0 both hold the theorem
symbol being attempted (e.g. `"*425"` for *4.25).  This was found by adding a
`"M001R000"` trace-expr that printed H0/W0.

**Solution:** `*trace-exprs*` hooks at three M001 cards:
- `"M001R000"` — reset all trace buffers, record `*current-proof-sym*` from H0
- `"M001R220"` — positive M001 exit (J4, proof found) → call `emit-proof-graph!`
- `"M001R260"` — negative M001 exit (J3, no proof)   → call `emit-proof-graph!`

`proof-graph!` was updated to take `filename` and `thm-label` parameters, so
the root node and DOT file comment are theorem-specific.  The DOT graph name is
quoted (`digraph "Problem *4.25" { }`) to avoid identifier restrictions.

Result: 23 `.dot` files written to `/tmp/lt-proof-NNN.dot` on every run,
one per theorem.

### 3. Timestamped logging and dotstar files

**Output directory:** `ltresults/` at the repo root, created automatically via
`ensure-directories-exist`.

**Per-run files** named `yyyymmddhhmm.log` and `yyyymmddhhmm.dotstar`.

**Log** (`*standard-output*` broadcast): `*standard-output*` is bound to
`(make-broadcast-stream *standard-output* log-stream)` around the entire
`load-ipl` call, so every `format t` in both the interpreter and LT program
goes to both the terminal and the log file — zero changes to J-functions.

**Dotstar** (`*lt-dotstar-stream*`): a global that `proof-graph!` checks; when
bound, it uses `make-broadcast-stream` to tee all DOT content to both the
individual `/tmp/` file and the dotstar.  `emit-proof-graph!` writes a
`// ====` separator before each theorem's graph so graphs are visually
delimited and easily extractable.

Dotstar format:
```
// ============================================================
// Problem *4.25
// ============================================================
digraph "Problem *4.25" {
  ...
}
```

## Architecture Notes

- **Why not CLOS `:around` on `ipl-eval`?**  M001 is called via the flat DESCEND
  loop (H1 stack manipulation), not via a recursive `ipl-eval` call.  Only J1,
  J18, and J100 subprocesses trigger recursive `ipl-eval`.  The `:around` hook
  IS defined and works for those, but M001 never appears as `start-symb`.

- **M001 exit cards:** M001R220 (J4, success) and M001R260 (J3, failure) are the
  two cards that fire just before M001 returns to its caller.  Trace-exprs fire
  *before* the card's J-function executes, so `emit-proof-graph!` is called while
  all proof data is still intact in `*card-cycles.ids-executed*`.

- **make-broadcast-stream** is the right tool for output tee — it requires no
  changes to existing print code, works transparently with all `format t` calls
  throughout both `iplv.lisp` and `LTFixed.liplv`'s J151/J152/J155/J156/J157
  print operations.
