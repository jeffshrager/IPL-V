# Handoff, 2026-10-03: interpreter changes vs. LT changes

Context: `iplv.lisp` here started as a copy of the HeuristicCoder forward copy
(`ExecutableArchaeology/repo/HeuristicCoder/lisp/iplv.lisp`, as of commit `7007da7` there).
It was then fixed until dmoews's Stefferud LT deck (`dmoews/`) reproduced the 1963
output. This file is for taking the interpreter back to the Heuristic Coder. Every change
is also marked in the source with `[Fixed: …]`, `[Added: …]` or `[Changed: …]`. For the
exact patch: `diff ~/Desktop/AIHistory/ExecutableArchaeology/repo/HeuristicCoder/lisp/iplv.lisp iplv.lisp`.

## Result of rerunning the Heuristic Coder on this interpreter (2026-10-03)

**Nothing changed.** With this `iplv.lisp`, the existing decks give byte-for-byte the same
output as the results saved in ExecutableArchaeology. The decks were not rebuilt, and all
output went to a scratch directory:

| Run | Compared with | Result |
|---|---|---|
| Heuristic Coder, faithful deck | `run/t1.txt` (50 lines) | identical |
| Heuristic Coder, SDSC deck | `run/t1-sdsc.txt` (52 lines) | identical |
| Annexer, printed list structure | `annexer/output.txt` (186 lines) | identical |
| Annexer, memory dump | `annexer/memory.txt` | identical |

The column risks rated below turned out to be harmless. The old print code was consistently
off by one: J154 and J160 set a 0-based 1W25, and J157 wrote at that 0-based index. The new
code uses a 1-based 1W25 and subtracts 1 when writing, so characters land in the same
physical columns. Only LT exposed the old bug, because it mixes print columns with the
input-side scanners (J180/J183/J184 counting from N1 = 1) and with margin-relative tabs.
The ratings below are kept as written before the rerun. The new `iplv.lisp` can be copied
over `HeuristicCoder/lisp/iplv.lisp`.

## 1. Changes to the interpreter (`iplv.lisp`)

### Loader / card reader
| # | Change | Why (manual / LT) | Heuristic Coder risk |
|---|---|---|---|
| L1 | A type-5 header with **P=4** (restart: "reload from tape SYMB") is a no-op. | Manual §18.5. In a single run, memory is already in place. LT has `5 X9` (J166 J165) and then `5 4 2`. The `2` used to be taken as a start symbol. | Low. The Heuristic Coder has no P=4 headers that I know of. |
| L2 | **PQ 01 is an integer data term only in data sections.** In routines it is an instruction ("execute the routine named in SYMB"). `read-card` and `next-card-row` take the load mode. | LT's `01W5`. Before, cols 51-61 were squeezed into LINK for every 01 card. | **Check.** `heuristic-run.card` has 12 PQ-01 cards. Any that sit in routine sections are now read as instructions (correct). Before, they were silently turned into integers. |
| L3 | A **lone regional character** in name/SYMB/LINK is read as `X0` (`A` → `A0`). | Manual: A and A0 are the same symbol. J186 inputs `A0`. LT spells it both ways. | **Check.** The Heuristic Coder has about 50 lone-regional fields. The program should be indifferent, but any Lisp-side code or script that looks up a cell by a one-letter name (`(cell "E")`) must now use `"E0"`. |
| L4 | In a symbol, **non-digits after the region character are dropped** (`YES` → `Y0`). Locals `9-n` are unaffected. | Symbols are a region character plus digits, as in J181. LT has `K31 YES`, which is tested against `Y`. | Low. The Heuristic Coder and annexer decks have no such fields. |
| L5 | An **all-blank alphanumeric term (PQ 21)** is kept as 5 blanks. It was `" "`. | LT's /16 has a blank external name, and J157 must enter it 5 columns wide. | Low to medium. Anything that compared a term with `" "` exactly. (J114 trims, so it is fine.) |

### Line input/output: columns are now 1-based everywhere (manual §16)
Before, J181, J186 and the J183/J184 scanners treated 1W25 as 1-based, and J154, J157,
J160 and J180-J182 treated it as 0-based.

| # | Change | Heuristic Coder risk |
|---|---|---|
| C1 | **J180** sets 1W25 = 1 after reading. It was 0. | **High.** The Heuristic Coder uses J180, J181, J182, J184 and J186. Its text front end and the annexer's reader may have been tuned to the old offsets. Rerun `run.sh` and `annexer/run.sh` and diff. |
| C2 | **J154** sets 1W25 = 1 (the left margin). It was 0. | **High** for print layout (5 uses). Output may shift right by one column. |
| C3 | **J156 and J157** enter at column 1W25 (1-based). | Same as C2. |
| C4 | **J160**: 1W25 = 1W21 + (0), with left margin 1, as the manual says. It was (0). | Tabs move one column right. |
| C5 | **J182** reads from column 1W25. It used to drop the first character. It takes the rightmost 5 columns of a longer field, and it sets H5 (+, or − if the field is blank). It used to leave H5 unchanged. | **High.** The Heuristic Coder uses J182 once. |
| C6 | **J156** prints an internal name `9-nnn` as `nnn` (in IPL-V, an internal symbol prints as an address). | Cosmetic. |

### J-functions
| # | Change | Why | Heuristic Coder risk |
|---|---|---|---|
| J1 | **J68**, when it is not the last cell: the cell it removes is returned to available space (symb/link set to 0), and **H5+ is set explicitly**. Before, H5 was left as it was. | The removed cell still linked into the list, which fooled J68's last-cell symtab scan into unlinking the wrong predecessor. That left a stray `0` at the end of LT's theorem lists (M62), and LT crashed. | **Medium.** The Heuristic Coder uses J68 twice; U119 deletes final symbols in a loop. Its results should only get *more* correct. The H5+ change matters if any caller relied on a leaked H5. |
| J2 | **J136** does not overwrite Q of a data term (Q=1 is the type code). | J120 + J136 of an integer made it print as `0` (LT's subproblem numbers). | Medium. The Heuristic Coder has 46 J136 calls. Local integer and alpha copies now keep their type, so J157 output of them changes from wrong to right. |

### Not changed, but verified
- Ackermann: `tests/Ackermann.liplv` → 61 and `tests/Acker.Ipl` → 125, both still correct.
- **Not rerun:** the Heuristic Coder (`run.sh` → `run/t1*.txt`), the annexer, EPAM, and the
  old `lt.lisp` / `LTFixed.liplv` (which already crashed at cycle 37 on the forward copy
  before these fixes).

## 2. Changes to LT

**None.** dmoews's `logic-theorist-1963-stefferud.iplv` runs byte-for-byte unmodified. It
includes the "save for restart / reload from tape" headers and LT's own card-input code
(M89 with J180-J186). The only harness step is that `dmoews/run.sh` appends
`logic-theorist-1963-stefferud-input.txt` to the deck, because input cards follow the
start card on the same stream. (dmoews's own patches are for the 7094 route only, in
`dmoews/7094/`; they are not used here.)

Result: the outcome matches 1963 for 24/24 theorems. The subproblem and substitution counts
match for 23/24, and the traces and proofs match line for line. The exception is *2.15,
which hits the effort limit at a different point because effort runs at about 0.66× the 1963
figure. Details are in `dmoews/README-lisp.md`.
